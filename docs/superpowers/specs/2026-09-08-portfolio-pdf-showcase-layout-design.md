# 포트폴리오 PDF 결합본 (showcase 레이아웃) 설계

작성일: 2026-09-08

## 배경

포트폴리오 PDF를 만드는 도구가 두 개 있고, 각각 다른 장점을 가진 출력물을 낸다.

| | `tools/build_portfolio_pdf.py` | `tools/build_general_portfolio_pdf.py` |
|---|---|---|
| 출력 | 15페이지 | 13페이지 |
| 데이터 | `data/hyundai_application_2026.json` + 스크립트 하드코딩 서술문 | 라이브 사이트 스크레이핑 |
| 이미지 | `D:/박종걸/박종걸_포트폴리오_2026.pdf`에서 추출 | 사이트에서 다운로드·캐시 |
| 폰트 | `C:/Windows/Fonts`의 Noto Sans KR | Nanum Gothic·명조 (OFL, 다운로드) |
| 강점 | 커버·프로필·요약·마무리 면의 편집 디자인 | 프로젝트 상세 면의 정보 밀도 |

전자의 프로젝트 면은 큰 이미지 한 장에 CHALLENGE/INSIGHT/EXECUTION/TAKEAWAY 서술과 KEY RESULTS 불릿을 얹는 구성이라 우측 하단 여백이 크고 스캔이 어렵다. 후자는 숫자 타일 그리드, 썸네일 스트립, 클릭 가능한 영상·자료 링크, 소제목이 붙은 상세 설명을 갖춰 훨씬 조밀하다.

두 출력물의 장점을 하나로 합친다.

## 목표

전자의 인트로·마무리 면과 후자의 프로젝트 상세 면을 결합한 15페이지 PDF를 만든다.

## 비목표

- 프로젝트 면 디자인 자체의 재설계 (검증된 현행 렌더러를 그대로 쓴다)
- 영문판(`--lang en`) 결합본
- 사이트(DB·어드민)나 웹 UI 변경

## 결정 사항

1. **교체 범위** — 주요 프로젝트 8개만 첨부본식 상세 면으로 바꾸고, 13페이지 PRODUCTION FOUNDATION(산꾼도시여자들·샤이니 미니 카드 2개)은 유지한다. 현재 사이트 내용 기준으로 15페이지가 되어 현행과 같다 (첨부본에서 프로젝트 10개가 모두 한 면에 들어갔으므로 8개도 들어간다). 내용이 늘면 결정 4에 따라 더 길어질 수 있다.
2. **뼈대** — `build_general_portfolio_pdf.py`를 확장한다. 데이터에 의존하는 어려운 부분(스크레이핑, 이미지 캐시·리사이즈, 링크 주석, 타일 파싱, 용량 예산)이 이미 동작하고, 유지할 면들은 좌표 기반 정적 레이아웃이라 이식이 쉽다.
3. **폰트·팔레트** — Nanum Gothic·명조 기준으로 통일한다. OFL 라이선스라 다운로드로 재현되고, 윈도우 설치 폰트 의존이 사라진다.
4. **분량** — 내용이 넘치면 기존 `(계속)` 페이지 로직을 그대로 쓴다. 총 페이지 수는 15에서 늘어날 수 있다.
5. **구 도구** — `build_portfolio_pdf.py`는 이번 작업에서 지우지 않는다. 결합본 확인 후 별도로 정리한다.

## 아키텍처

### CLI

`build_general_portfolio_pdf.py`에 `--layout` 옵션을 추가한다.

- `--layout general` — 기본값. 현행 13페이지 출력을 그대로 유지한다.
- `--layout showcase` — 신규 15페이지 결합본.

기본값을 `general`로 두어 기존 동작과 기존 호출 방식이 바뀌지 않게 한다.

### 모듈 분리

유지할 7개 정적 면의 렌더러를 새 모듈 `tools/showcase_pages.py`로 분리한다.

- **하는 일**: 문서 객체와 데이터를 받아 정해진 면을 그린다.
- **쓰는 법**: `render_cover(doc, data)`처럼 면 단위 함수를 호출한다. 각 함수는 한 면을 그리고 끝낸다.
- **의존**: reportlab 캔버스 API와 `build_general_portfolio_pdf`의 팔레트·폰트 상수. 스크레이핑이나 네트워크를 직접 건드리지 않는다.

프로젝트 면 렌더러(`build_general_portfolio_pdf.py`의 기존 코드)는 수정하지 않는다. 결합본은 그 렌더러를 8개 프로젝트에 대해 호출할 뿐이다.

### 데이터 흐름

```
라이브 사이트 (DB + 어드민 편집)
  └─ parse() ─→ 프로필·수상·프로젝트 10개·인물 사진·프로젝트 이미지

data/hyundai_application_2026.json
  └─ portfolio_summary, 커버 카피, EXPERIENCE MAP 카드, HOW I WORK 카드

          ↓ showcase 레이아웃이 둘을 조합

15페이지 PDF
```

프로젝트 내용의 원본은 사이트다. 어드민에서 고치면 다음 빌드에 반영된다. JSON은 사이트에 대응 필드가 없는 편집 카피(요약 숫자, 방법론 카드)만 담당한다.

### 페이지 구성

| 면 | 내용 | 출처 |
|---|---|---|
| 1 | 커버 — 헤드라인 3행 + 인물 사진 | JSON 카피 + 사이트 사진 |
| 2 | 프로필 — 경력 / 학력·어학 / 수상 3단 | 사이트 |
| 3 | IMPACT AT A GLANCE — 숫자 타일 4개 + 채널 설명 3단 | JSON `portfolio_summary` |
| 4 | EXPERIENCE MAP — 4카드 | JSON (신규 필드) |
| 5–12 | 주요 프로젝트 8개 — 상세 면 | 사이트 (기존 렌더러) |
| 13 | PRODUCTION FOUNDATION — 미니 카드 2개 | 사이트 |
| 14 | HOW I WORK — 3단계 카드 | JSON (신규 필드) |
| 15 | 클로징 — 연락처 + SELECTED RECOGNITION | 사이트 + JSON |

프로젝트 8개는 사이트 정렬 순서에서 산꾼도시여자들·샤이니(13페이지로 가는 CJ ENM 제작물) 둘을 뺀 나머지다.

스크레이핑한 데이터에는 `key` 필드가 없고 제목만 있으므로, 미니 카드로 뺄 둘은 JSON의 신규 키 `showcase_production_titles`에 제목 문자열 목록으로 지정한다. 코드에 제목을 하드코딩하지 않는다. 매칭은 공백을 정규화한 뒤 정확히 일치하는지로 판단하고, 목록의 제목이 사이트에서 발견되지 않으면 경고한다.

### 콘텐츠 이동

4페이지와 14페이지의 카드 문구는 현재 `build_portfolio_pdf.py`에 파이썬 리터럴로 하드코딩돼 있다. 이를 `data/hyundai_application_2026.json`의 신규 최상위 키 `experience_map`, `working_method`로 옮긴다. 이 레포는 이미 편집 카피를 JSON에 두는 패턴을 쓰고 있고, 문구 수정에 코드 변경이 필요 없어진다.

### 로컬 의존 제거

결합본은 사이트와 JSON만으로 빌드된다. 현재본이 요구하는 두 로컬 자원이 필요 없어진다.

- `D:/박종걸/박종걸_포트폴리오_2026.pdf` (이미지 추출용) → 사이트 이미지로 대체
- `C:/Windows/Fonts`의 Noto Sans KR → 다운로드 캐시되는 Nanum

결과적으로 다른 PC나 CI에서도 동일한 PDF가 나온다.

## 출력 경로

결합본이 제출용 산출물이므로 기존 경로를 이어받는다.

```
C:/Users/user/Documents/Codex/2026-09-07/new-chat/outputs/박종걸_포트폴리오_2026.pdf
```

`build_portfolio_pdf.py`가 같은 경로에 쓰기 때문에, 구 도구를 실행하면 결합본을 덮어쓴다. 구 도구를 정리할 때 함께 해소된다. 그때까지는 구 도구를 실행하지 않는다.

## 오류 처리

- **사이트 접근 실패** — 캐시된 이미지·폰트가 있으면 쓰고, 페이지 HTML을 못 받으면 명확한 메시지와 함께 실패한다. 낡은 데이터로 조용히 빌드하지 않는다.
- **인물 사진 없음** — 커버는 사진 없이 텍스트가 폭을 넓혀 채운다 (기존 프로필 면이 쓰는 방식과 동일).
- **JSON 키 누락** — `portfolio_summary`, `experience_map`, `working_method`가 없으면 어느 키가 빠졌는지 밝히고 실패한다.
- **프로젝트 수 불일치** — 사이트 프로젝트에서 미니 카드 2개를 뺀 결과가 8개가 아니면 경고하고, 있는 만큼 렌더링한다.
- **용량 초과** — 기존 `--max-mb` 단계적 축소(DPI·JPEG 품질)를 그대로 쓴다.

## 테스트

- `tests/test_portfolio_pdf.py` — 페이지 수 단언을 `== 15`에서 `15 <= n <= 18`로 바꾼다. 2MB 미만, 필수·금지 문자열 검사는 유지한다.
- `tests/test_showcase_pages.py` (신규) — `showcase_pages.py`의 순수 함수 단위 테스트. 카드 배치 좌표 계산, JSON 키 검증, 프로젝트 8/2 분리 로직.
- `tests/test_portfolio_pdf_tool.py` — 변경 없음. `split_kpi`·`parse`는 건드리지 않는다.
- 회귀 확인: `--layout general` 출력이 현행 13페이지와 동일한지 확인한다.
